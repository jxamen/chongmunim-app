## 1 · 2컷 — 한 장의 사진이 두 컷으로 나뉜다 (이번 의뢰의 핵심)

스토어 목록에서 컷은 **나란히** 보인다. **큰 폰 목업 하나를 1컷과 2컷의 경계에 걸쳐** 둔다 —
1컷 오른쪽에서 잘린 폰이 2컷 왼쪽에서 이어져 두 장이 **한 장면**으로 읽혀야 한다. 배경색 · 장식도 경계를 넘어 이어진다.

- **1컷**: 왼쪽 위 로고(아이콘 캐릭터 + 「총무님」), 큰 헤드라인, 받침글. 폰의 왼쪽 절반.
- **2컷**: 폰의 오른쪽 절반 + **설명(콜아웃)**. 홈 화면의 부분을 가리키는 말풍선/지시선 2~3개:
  「모임 잔액과 이번 달 수입 · 지출」 「예산이 얼마 남았는지」 「처리할 지급 요청」 처럼 **화면에 실제로 보이는 것**만 가리킨다.
- 폰은 살짝 기울여도 좋다(당근 1–2컷처럼). 경계선이 폰 화면의 중요한 숫자를 가르지 않게 위치를 잡는다.

## 화면 원본(`store/raw/`) — 없으면 먼저 찍는다

지금 `store/raw/` 는 비어 있다. 앱을 **웹으로 띄워(`npx expo start --web`) Playwright 로 찍는다** — 당근 `raw/` 도 웹 캡처였다.

- 뷰포트 **390 × 844, deviceScaleFactor 3**(= 1170 × 2532). 상태바는 없다 — **가짜 상태바를 그려 넣지 않는다.**
- 로그인 · 서버가 필요하면 **Playwright 의 `page.route` 로 API 응답을 가로채 시연용 모임 데이터를 준다.**
  응답 모양은 `src/api.ts` 와 각 화면 코드에서 읽는다. 진짜 서버에 쓰기 요청을 보내지 않는다.
- 시연용 모임: 이름 예 「주말 등산 동호회」, 회원 8~10명(흔한 한국 이름 · 성만 다른 가짜 이름), 금액은 현실적인 동호회 규모
  (월 회비 30,000원, 잔액 수십~백만 원대). **실제 이용자 이름 · 실제 모임을 쓰지 않는다.**
- 시연 모임은 **구독(pro) 모임, 보는 사람은 총무**로 둔다 — 회비 · 공지 · 지급 요청 · 마감은 구독 기능이라
  무료면 구독 안내가 뜬다(`AGENTS.md` 「구독」 · `src/cm/plan.ts`).
- 운영 값은 그대로: 가격 · 무료 한도(한 번에 1장 · 회원 10명)는 `store/LISTING.md` 와 앱 코드 값. 화면에 안 나오면 넣지 않는다.
- 캡처 스크립트는 `store/design/capture.js` 로 남겨 다시 찍을 수 있게 한다. 원본 코드(`src/`)는 **고치지 않는다.**
- 3컷(영수증)은 웹에서 카메라가 안 된다 — 앨범 고르기 → 읽은 결과 확인 화면을 찍는다(읽기 응답도 가로챈다).
  영수증 사진이 필요하면 CSS/HTML 로 그린 그럴듯한 가짜 영수증 이미지를 만들어 쓴다.

## 지켜야 할 것

- **총무님은 앱테크(리워드) 앱이 아니다** — 포인트 · 현금 · 보상 같은 말을 쓰지 않는다.
- 과장 금지 — 「무조건」 「100%」 「완벽」 같은 말은 심사에서 걸린다. 없는 기능을 그리지 않는다.
- 폰 목업(베젤 · 둥근 모서리 · 그림자)은 CSS 로 직접. 반경 60px 정도, 검정 베젤 12px.
- 글자는 컷 가장자리에서 **80px 이상** 띄운다. 헤드라인은 목록에서 세로 300px 로 줄어도 읽혀야 한다.
- 끝나면 `store/README.md` 에 당근처럼 폴더 설명 · 다시 굽는 법 · 캡처 방법을 적는다.
- 커밋 · 푸시는 하지 않는다(맡긴 쪽이 확인하고 한다).
